# 22. 我的应用需要评估什么：业务目标→能力→指标

> **如果只读一节**：自定义评估的 3 步：(1) 拆业务目标为能力维度 (2) 每个能力设计指标 (3) 每个指标设计测试集。**没有第 1 步 = 自欺欺人**。

## 22.1 本章目标

读完后你能：

- 把"做一个 AI 客服"拆解为可评估的能力
- 为每个能力设计指标
- 知道能力拆解的 4 种方法
- 知道常见能力维度模板

## 22.2 核心方法论：业务目标 → 能力 → 指标

```
[业务目标] "让客户满意度提升 20%"
   ↓
[能力维度] 1. 准确理解客户问题
          2. 给出正确的产品信息
          3. 礼貌且有同理心
          4. 快速响应
   ↓
[指标设计] 1. 意图识别准确率 (F1)
          2. 答案事实性 (Faithfulness)
          3. 用户满意度 (CSAT)
          4. P95 延迟
   ↓
[测试集]   各 200+ 题
```

## 22.3 能力拆解的 4 种方法

**方法 1：用户旅程**

```
打开应用 → 提问 → 等待回答 → 收到答案 → 后续追问 → 结束

每步都是一个能力维度
```

**方法 2：失败模式（FMEA）**

> 想"哪里会失败"，每个失败点就是一个能力。

```
AI 客服可能失败：
- 没听懂客户问题（意图理解）
- 答错产品信息（事实性）
- 答得太啰嗦（简洁性）
- 暴露内部 prompt（安全性）
- 处理不了情绪化客户（同理心）
```

**方法 3：业务关键指标（KPI）反推**

```
业务 KPI: 客户留存率
   ↓
影响 KPI 的因素: 客服满意度
   ↓
影响满意度的因素: 答案准确、速度、态度
   ↓
→ 评估这 3 个能力
```

**方法 4：竞品对标**

```
竞品 A 强在: 多语言
竞品 B 强在: 情绪识别
   ↓
我们的能力维度: 中文+多语言 + 情绪识别
```

## 22.5 指标设计的 5 个原则

**原则 1：可测**

```
❌ "AI 应该更聪明"
✅ "AI 在 200 道客服题上 F1 > 0.85"
```

**原则 2：与业务相关**

```
❌ "GSM8K 准确率 95%"
✅ "退款问题回答准确率 95%"
```

**原则 3：可复现**

```
❌ "凭感觉"
✅ "同一题问 3 次，3 次答案一致"
```

**原则 4：可对比**

```
❌ "我觉得好"
✅ "新版本 vs 旧版本，用户偏好胜率 60%"
```

**原则 5：可监控**

```
❌ "偶尔看看"
✅ "每天 9 点自动跑，输出到 Slack"
```

## 22.6 完整实战：AI 法律咨询助手

**业务目标**

> "为中小企业提供低成本法律咨询，替代 50% 的律师电话咨询。"

**能力拆解**

```
P0 能力（必须达到，否则不可用）：
1. 法律法规引用准确（不能编造法条）
2. 案件类型识别准确
3. 法律建议保守（不能给出冒险建议）
4. 风险点识别（避免给客户错误预期）

P1 能力（达到后提升体验）：
5. 多轮对话（能追问澄清）
6. 同理心（理解客户焦虑）
7. 拒答能力（超出范围时引导律师）

P2 能力（差异化）：
8. 引用案例库
9. 输出结构化文档
10. 多语言
```

**指标设计**

| 能力 | 指标 | 目标 |
|---|---|---|
| 法规引用 | 法规正确率 | > 95% |
| 案件类型 | 分类 F1 | > 0.90 |
| 建议保守度 | 评分（律师评） | > 4.0/5 |
| 风险点 | 召回率 | > 90% |
| 多轮对话 | 上下文保持率 | > 0.85 |
| 同理心 | 人类评分 | > 4.0/5 |
| 拒答 | 拒答准确率 | > 90% |

**测试集来源**

| 来源 | 数量 | 备注 |
|---|---|---|
| 公开法律题（Bar Exam） | 100 | 基线 |
| 内部历史咨询 | 500 | 真实场景 |
| 律师手动编写 | 200 | 覆盖边界 |
| 合成（LLM 生成） | 200 | 长尾覆盖 |

## 22.7 评估的"最小可行"路径

**第 1 周：MVP 评估**

```
1. 准备 50 道真实用户题
2. 跑 LLM-as-Judge
3. 人工抽检 20 个
4. 输出报告
```

**第 2-4 周：扩展测试集**

```
5. 增加 200 道
6. 加 4 大指标
7. 跑 + 出报告
```

**第 2 个月：自动化**

```
8. 集成到 CI/CD
9. 每天跑
10. 监控告警
```

**第 3 个月：上线 A/B**

```
11. 真实流量 A/B
12. 收集真实反馈
13. 持续改进
```

## 22.8 能力评估的 4 个常见错误

**错误 1：只看准确率**

```
准确率 99% ≠ 用户满意
```

→ 加 CSAT、Faithfulness、Helpfulness。

**错误 2：忽略失败成本**

```
"拒答"是 OK 的
"编造答案"是危险的
```

→ 不对称加权。

**错误 3：测试集与真实分布脱节**

```
测试集：5 分类问题
真实：100 种意图
```

→ 真实数据优先。

**错误 4：评估"分数高"就发布**

```
MMLU 90% ≠ 在你业务上 90%
```

→ 业务 hold-out 测试。

## 22.9 章节小结

- **业务目标 → 能力维度 → 指标 → 测试集** 是核心方法论
- 能力拆解 4 方法：用户旅程 / FMEA / KPI 反推 / 竞品
- 指标设计 5 原则：可测 / 业务 / 复现 / 对比 / 监控
- MVP → 扩展 → 自动化 → A/B 是部署路径
