# 实习生视角评审

> 评审人背景（真实情况）：入职 3 个月，本科毕业，会一点 JS（写过 Vue 页面、跑过 npm test），AI 知识全部来自短视频和公众号。被安排"把这本评估的书读了"。
> 实际阅读范围：第 0 章（术语表）+ 第 1 章（什么是评估）+ 第 9 章（硬核评测）+ 最后一章（结课自测与 FAQ）。
> 小提示：派活的人跟我说"去看第 28 章自测"，我翻过去发现第 28 章是"评估一个代码生成 Agent"的案例，自测其实在**第 31 章**。我一开始翻错了章。

## 总评分（1-10）：6.5/10
- 对小白的友好度：6/10（对我这种"前端背景 + AI 只懂梗"的人，术语表和前端类比是真用心了，但一到正文密度就上来了）
- 我读完了多少：抽读的 4 章读完约 90%（第 9 章的 9.6 KernelBench 和 9.7 MLE-bench 是跳着看的）；按这个密度让我通读 32 章，我估计只能读完 30%，而且大部分是跳读
- 推荐给其他实习生吗：**看情况**。会推第 0 章 + 第 1 章 + 第 9.9 节这三块；不会推"从头到尾读"。想一口气读完的实习生大概率在第 5-8 章（各学科基准）那儿阵亡

## 劝退点（我关掉页面的瞬间）

按真实时间顺序记：

1. **第 0 秒：网站打不开。** 我第一反应是点 http://evals.zenheart.site/ ，浏览器直接弹"您的连接不是私密连接"（证书错误 ERR_CERT_COMMON_NAME_INVALID），我一度以为这个链接是假的，差点直接去搜别的资料了。书的内容我是后来在仓库 `book/chapters/` 里看的。这个对"被派来读书的实习生"是致命的——我根本不知道去哪读。（我看了下 git 记录，团队最近几条提交都在折腾 CNAME 和 SSL 证书，可能是临时的，但对我这种当天打开的人就是当天劝退。）

2. **第 1 章 1.2 节"76 年简史"：9 个节点一次性砸过来。** 图灵测试、ELIZA、BLEU、GLUE、SuperGLUE、GPT-3、MMLU、HELM、Arena、GSM1k、SWE-bench……一个自然段一个专有名词套餐，还带论文编号和百分比。我在第三个节点（BLEU）开始快扫，靠"加粗句"支撑着往后滑。ELIZA 那个"用户把 200 行程序当真人、作者本人深感不安"的故事和 GSM1k"换了张同考纲的新卷子，掉 8 个分"的故事是两个救命的钩子，没有它们我 1.2 节就切走了。

3. **第 9 章开场白就甩前置依赖。** "7.5（SWE-bench）与 7.5.7（ABC 论文）是本章的直接前置"——我没读过第 7 章，这句话对我就是"本章你注定缺一块"。后面 9.5.2 还冒出一个 "cons@k"（说"这与第 6 章 AIME 的 cons@k 形成对照"），术语表查不到，第 6 章我没读，这个词我就永远是黑盒。

4. **9.6 KernelBench：我彻底懵的那一节。** "GPU kernel（CUDA/Triton）"、PyTorch 参考实现、访存模式——这些词没有任何一个在术语表里，正文也不解释，默认你是搞深度学习的。前端类比（"把全量重算的列表改成虚拟滚动"）救了我一半，但"kernel 到底是个啥东西"我还是不知道，这节我是纯跳读的。

5. **最后一章 FAQ 中段：缩写字符海。** Q12-Q15 一口气出现 RULER、TruthfulQA、SimpleQA、POPE、HaluEval、CMMLU、C-Eval、XCOPA、Flores-200、MTEB……没有任何一个能在术语表查到，也没有"详见第 X 章"的指针。我读到 Q14 直接心里一句"算了，这段与我无关"就滑过去了。

## 查术语表的真实体验（查到了吗/解释能懂吗）

**查到且能懂的（好评）：**
- Token、Prompt、Temperature、RAG、Agent、Elo 这些核心词，前端类比确实灵。"Elo ≈ 王者荣耀的排位分"——我是刷短视频看懂排位机制的，这个类比直接命中我。"RAG ≈ 开卷考试"、"Temperature ≈ 0 是稳定复读机"，都是我看一遍就记住的。
- "如果只读一节"说"遇到不懂的术语先来翻这里"，这个使用方式本身是成立的，我确实翻了三四次。

**查不到的（这本书最伤我的地方）：**
- **全书出场率最高的那些基准名，术语表全都没有**：MMLU、HumanEval 只在"13. Benchmark"词条里顺嘴提了一句，而 SWE-bench、GSM8K、GSM1k、AIME、Arena、RAGAS、cons@k、hold-out、canary tokens、SOTA，我在术语表里一个都搜不到（我用 Ctrl+F 逐个验证过）。第 0 章开头承诺"每个术语首次出现就有定义"，但 RAGAS 在最后一章第一次出现就是一条命令，faithfulness、context_precision 四个指标零解释——承诺和现实对不上。
- 术语表还有个小瑕疵：第 16 条叫"Elo / Bradley-Terry"，第 25 条又单独一条"Bradley-Terry"，同一个词两个词条，我更晕了。
- Bradley-Terry 的解释是"比 Elo 更统计化的偏好评分模型"——看了等于没看，但我承认这种词查到了也就是个心理安慰。

**结论：术语表能救"概念词"（Judge、Metric、RAG 这类），救不了"专名"（基准名、指标名、统计词）。而恰恰专名才是我卡壳的主因。**

## 自测题真实作答记录（做了哪几题、对了几题、卡在哪）

先说一个体验问题：**最后一章的 8 道自测题，答案就印在题目下面**，我根本没法闭卷，只能用手挡着答案"假装自测"。另外第 1 章和第 9 章每章末尾的"验收自测"（各 6 题）**全书找不到参考答案**，我做完了没法对答案，做错的都不知道。

按"只读过第 0、1、9 章 + 挡着答案"的条件，我的真实作答：

- **Q1 向产品经理解释评估**：✅ 答上了。"用一批固定的题目 + 固定的打分规则，把'模型好不好'变成能对比的数字；因为模型输出是随机的，靠'感觉'不行。"这题是第 1 章喂给我的。
- **Q2 评估的 4 步**：✅ 出题→答题→打分→看报告。我其实是靠第 1 章 1.6 的"任务→生成→评分"三动作 + 常识凑出来的，标准答案里的"四步法"应该在第 3 章，我没读过也蒙对了大概。
- **Q3 LLM-as-Judge 的 4 个偏差**：3/4。位置偏差 ✅（第 1 章 Goodhart 那节提过"裁判做位置交换"）、长度偏差 ✅（AlpacaEval"模型学会写长来赢"我记住了）、自偏好 ✅（连蒙带猜：裁判偏心自己人）、**格式偏差 ❌**（完全没见过，这内容在第 13/18 章，我没读）。
- **Q4 刷榜为什么严肃**：✅ 数据污染（GSM1k 换卷掉 8 分的故事直接支撑）+ 特殊 prompt 不写明。"best-of-N"这个词我写不出来，我只能写"跑很多次取最高分"。
- **Q5 写 30 行阶乘评估代码**：✅ 能写，照第 1 章 1.7 的模板改。**但我发现参考答案自己踩了第 1 章刚教过的坑**：它用 `output.includes(t.expected)` 判分，没做归一化——模型答 "3,628,800"（带逗号）就会被误判错，而第 1 章专门强调过"exactMatch 太脆，要先提取数字"；参考答案也没有第 1 章特意写的 API key 检查，而且代码里在模块顶层直接 `await`，第 1 章特意提醒过"普通 .ts 用 node 跑不了，要 npx tsx"，答案里啥也没说。**照抄这段答案的新手会正好撞上第 1 章警告过的报错。**
- **Q6 RAGAS 评估命令**：❌ 完全做不了。RAGAS 这个词全书没定义过，术语表查不到，四个指标名不认识。只能原样抄答案，抄完也不知道自己在干嘛。
- **Q7 客服 5 大指标**：3/5。我能想到准确率、用户满意度、响应速度；"忠实性 Faithfulness"和"拒答准确率"没读过第 20 章，想不出来（拒答那个半猜到，第 1 章提过"无法登录拒答率"的例子）。
- **Q8 三个模型怎么选**：半对。大流程我能编出来（定目标→出题→跑分→看榜→灰度上线），但标准答案里的"500 题、公开 20% + 人工 30% + 回流 30% + 合成 20%、4 个榜单对账"这些数字全是第 22-23 章的内容，我没读过，这题本质是让我背口诀。

**记分：8 题里独立做对 2.5 题、半对 2 题、做不了 1 题、纯抄 2.5 题。** 前提还是我"假装读完了全书"。诚实说：这 8 题不是自测，是**回忆测验 + 口诀默写**——它默认你把 32 章全读完了，而且它把答案直接糊你脸上。

30 分钟后的真实状态（我给自己掐了表）：

- 5-20 分钟：第 1 章。1.2 简史信息量爆炸，我在 BLEU 那段开始快扫；ELIZA 和 GSM1k 两个故事把我拽回来两次。

## 直觉判断（哪里"感觉在装 deep"、哪里是真干货）

**装 deep 嫌疑（我的直觉反应）：**
- "76 年历史、9 个关键节点"——第一章就要我装下 76 年学术史，信息量 > 必要量。实习生只需要 3 个故事：ELIZA（人会被骗）、GSM1k（会背题）、Arena（人群当裁判）。
- "确定性锚点""能力构念""操作定义"——书里反复用的这类词，一听就是从论文里搬来的，第一次出现都不解释。
- 最后一章的"关键金句"：**"4 来源测试集混合""5 个榜单对账""与人类一致率 ≥ 80% 是元评估门槛"**——为什么是 4？为什么是 5？为什么是 80？金句不解释，像背口诀。而且"元评估"这个词我根本没接触过（在第 26 章），金句直接拿它当已知概念用。还有"评估 = 单元测试 + E2E + 性能 + A/B"这句在第 1 章和第 31 章各出现一次，措辞还不太一样，像咒语不像知识。
- "Spearman r² = 0.36"——直接甩统计量，不解释 Spearman 是啥。短视频教过我"正相关"，所以我半懂不懂地滑过去了。

**真干货（我会截图发实习生群的）：**
- 第 1 章 1.7 的可运行代码：连"要联网、要花 API 钱、CommonJS 的 .ts 跑不了 top-level await、密钥别硬编码"都写了。这是全书最为我这种人着想的一段，没有之一。
- ELIZA 效应和 GSM1k 反刷榜这两个故事——短视频级别的戏剧性，但讲的是正经道理（"评估者会被被评估对象欺骗""分数可能来自记忆"）。
- 第 9 章"**数一数有几家厂商的旗舰发布正文引用了它**"来判断一个新评测处在生命周期哪一段——这是个我明天上班就能用的土办法。
- 第 9 章把 Terminal-Bench 类比成"新员工入职第一天裸机装机"，SWE-Lancer 用"美元"当分数单位——"完成了 40% 的任务"不如"赚到了 100 万里的 40 万"直观，这个说法我能直接转述给运营听。
- 第 1 章的诚实：引用 OpenAI 那句"Evals are the bottleneck"时，明确标注"属二手转述、未检索到官方一手原文，此处仅作旁证"。**敢于承认自己没查到的书，反而让我更信它其他没标注的部分。**还有 FrontierMath 那个"收了 OpenAI 资助没披露"的事件，敢把厂商的遮羞布写进教材，这在公众号文章里看不到。

## 如果我是这本书的产品经理，我会改的 3 件事

1. **把术语表从"概念词典"升级成"全书专名索引"。** 现在的 20+11 个词条只覆盖概念词，但真正卡住实习生的是 SWE-bench、GSM8K、MMLU、AIME、Arena、RAGAS、cons@k、hold-out、canary、Cohen's Kappa 这些专名——它们才是第 5-15 章的主角。做法很便宜：在第 0 章后面加一张"按字母排序的专名速查表"，每条一句话定义 + "详见第 X 章"。顺手把第 0 章那句"每个术语首次出现就有定义"的承诺兑现掉（RAGAS 现在就是反例），并合并 Elo/Bradley-Terry 的重复词条。另外把网站证书修好——书再好，链接点开是"连接不是私密连接"，第一秒就全剧终。

2. **改造自测系统，让它真的能自测。** 三件小事：(a) 每章"验收自测"补参考答案，至少给一个"答案锚点"（"见第 X 章 X.X 节"），不然做错了都不知道；(b) 最后一章的 8 道题和答案分成两个区（先答题区、后答案区），别把答案印在题干下面——现在的"自测"实际是"阅读理解"；(c) 把第 31 章那段阶乘参考代码按第 1 章自己立的规矩改对（判分先做数字归一化、补 API key 检查、注明要用 npx tsx 跑），否则新手照抄必撞坑——**教学书的参考答案自己违反自己的教学规范，这是最伤信任的一处。**

3. **给硬核章节加"实习生逃生通道"。** 第 9 章这类章节，在每节标题后面直接标注难度和可跳过性，比如"9.6 KernelBench（GPU 方向，非算法岗可跳）"；"如果只读一节"是全章最有效的设计（我就是被它从手机边拉回来的），建议每章的开头承诺和章内小节一一挂钩——第 9 章开头说读 9.9，那 9.3-9.8 就该明确说"只看每节第一段的黑体定义 + 对比表即可"。再狠一点：每 3 章配一页"实习生包"——这 3 章只需记住的 5 句话 + 可放心跳过的小节清单。32 章的书，读者需要的是"官方允许我跳读"的许可，现在这种感觉只能靠读者自己赌。
