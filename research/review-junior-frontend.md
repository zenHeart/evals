## 卡住的地方（按严重度）

### 🔴 放弃点（想直接关掉）

没有。我全程没有出现"关掉吧"的念头。最接近放弃边缘的有两处，降级为 🟡 记录。

### 🟡 困惑点（重读才懂/没懂）

**1. 第 3 章 3.4.3 "likelihood-based 作答协议"——我照着做不出来。**
原文说 likelihood 路线"不生成文本，直接比较各选项完整字符串的条件概率，取最高者"。问题是我只会调 chat completions API，**我从没见过一个能"返回某个字符串的概率"的接口**。`doc_to_text + target_delimiter + doc_to_target` 的续写概率这套描述，我是结合第 16 章 lm-evaluation-harness 的上下文才勉强推断出"这是本地模型 harness 才能干的事，我拿 gpt-4o-mini 跑不了"。缺一句显式说明："这条路线需要能拿 logprobs 的 API（或本地模型），托管 chat API 用户请走 generation-based"。我第一次读时卡了约十分钟，甚至以为自己漏了什么 SDK 能力。

**2. 第 3 章 3.6 统计三连（Wilson → McNemar → bootstrap）连续轰炸。**
三个统计工具、三段代码背靠背出现，中间没有给初级读者喘息的"你只需要记住什么"分层。Wilson 那段有具体数字锚点（100 题 70% → [60.4%, 78.1%]）我能跟上；到 McNemar 的 `binomCoeff` 循环我就只能"选择相信这段数学是对的"；bootstrap 的 LCG 伪随机实现我知道是可复现性妥协但读着吃力。第 4 章 4.6 又出现了一个**简化版** McNemar（卡方近似 `> 3.84`），和 3.6.2 的精确二项版实现不一致——没人告诉我两版的关系，我得自己意识到"第 3 章是精确版、第 4 章是近似版"。建议在 3.6 开头加一句"本节读不懂代码没关系，记住三个结论即可"，把三个结论列出来。

**3. 全书自测题没有答案。**
第 1 章 1.10 验收自测 6 题、第 31 章 31.2 结课自测 8 题，我都在页面上实际展开验证过：**只有题目，没有任何参考答案**（我 grep 了整页 innerText，第 1 章和第 31 章的"答案"字样全部来自正文，不是自测答案）。自测折叠按钮写着"先作答再对照"，但对照材料不存在。我做完"下面哪个是指标而不是基准"只能猜自己对了没。对一个明确宣称"不再被 LLM 黑话劝退"的入门书，这是最影响学习闭环的缺口。

**4. 第 2 章 2.2.1 "评估的递归"第一遍没读懂。**
RM（reward model）→ 训练信号 → "评估器 = 训练器"的三层递进，第一遍我读得囫囵，第二遍才理顺。对训练侧读者这可能很自然，但我是应用层前端，第 2 章开头刚被科普完什么是 SFT，紧接着就上 RLHF 元评估，跨度略大。好在这节的收尾推论写得极清楚（"任何 LLM-as-Judge 方案必须先校准裁判"），我把这句记住了。

**5. 第 4 章 "构念效度" 标题先于解释。**
"构念"是心理测量学术语，4.1 的目标列表里就出现了，但定义在 4.2 才给。我第一眼以为是什么编程概念（前几章一直在讲效度=可信度），带着错误预期读了半页。小问题，把定义挪到目标列表后面一行即可。

### 🟢 小磕绊

1. **首页搜索浮层挡住章节链接**。我在搜索框输入 "pass@k" 后想点下面的"第 1 章"链接，点击被搜索结果面板拦截（Playwright 报 `sr-item ... intercepts pointer events`），必须先清空搜索。真实用户也会撞到。

## aha 时刻（最有价值的讲解）

1. **第 4 章 4.2 构念效度 + Lighthouse 类比**："Lighthouse 分数高 = 用户体验好"并不成立——测的是实验室代理指标。这个类比对我是一次精确打击，因为我真的见过有人拿 Lighthouse 100 分向老板证明产品好用。"分数是构念的代理，不是构念本身"这句话我记住了，而且立刻想到工作里的对应物：接口自动化通过率 ≠ 用户没报障。

2. **第 14 章 14.6.1 cons@64 vs flaky 测试**："cons@64 就是 flaky 测试重跑 64 次取多数……CI 里重跑 flaky 测试到通过为止是反模式，cons@64 却是合法测量——区别在于前者是挑最好的结果，后者是报告一个预先声明的聚合口径。" 这一段让我彻底分清了两件以前混为一谈的事，也是全书对我既有认知修正最大的一个类比。

3. **第 7 章 7.2.1 字符串匹配 ≈ Jest 快照测试**："只验证输出长得和上次一模一样，不验证逻辑是否正确"。配合那个 `sum(n for n in nums if not n & 1)` 语义等价样例，我 30 秒懂了为什么代码评估必须真实执行，以及为什么 HumanEval+ 要把测试密度乘 80。

4. **第 1 章 1.6 四概念表**：基准=题库、指标=规则、评分器=裁判、排行榜=公示栏，配上 `toBe()` vs `toBeCloseTo()` 的指标类比。这是全书写得最经济的一张表，30 秒讲清四个概念，我后来读第 7、14 章全程靠它定位。

5. **第 3 章 3.4.5 双过滤管道**：lm-eval 对同一份 gsm8k 输出同时跑 strict-match 和 flexible-extract 并排报告，"差距大 = 格式遵从问题；都低 = 真能力问题"。这跟我排查线上"200 OK 但 body 错了"的静默 parser 故障是同一套思路——把抽取器的不确定性显式化。错题四分法（knowledge / reasoning / format / extraction）里"extraction failure 是你的 bug 冒充模型的错误"这句我直接抄进了笔记。

6. **第 14 章读报告五问法（14.5）+ 锚点四原型（14.3）**：协议、采样、子集、锚点、缺席。"同一模型单次 72.5% vs 并行 80.9%，分差 8.4 个点，两种报法都合法"、"限定词每加一个，'第一'含金量降一级"。这是全书实用性密度最高的方法论，我准备把它贴在工位上。"+550% 先找基数"（14.4.5）也是。

7. **第 17 章 17.5.2 决策 7**："`process.exitCode` 是门禁的全部接口——过则 0、挂则 1，所有 CI 都认这个语义。" 以及决策 3 mapPool："无限 `Promise.all` 遇到限流的结果不是报错而是静默丢数据"。这两条是纯前端知识库里就该有的工程常识，讲得比很多前端文章清楚。

## 站点体验

以 Chrome 实测（http://evals.zenheart.site/）：

**导航与阅读流：好。** 首页按 7 个部分分组列出 32 章，带"第 0 部分术语速查（建议先读）"的引导；章节页有面包屑（首页 / 第 1 部分 / 第 1 章）、右侧"本页目录"锚点导航、页尾上一章/下一章链接。我作为读者能顺畅地从第 0 章一路点下去，一章读完接下一章没有断点。

**搜索：好用，有一个交互 bug。** 在首页搜索框输入 "pass@k"，实时返回带高亮片段的结果（第 0、4、6、7 章命中），点击可跳转。但搜索结果浮层展开时会**挡住下方的章节列表**，点击章节链接被浮层拦截（我实测点"第 1 章"点了三次都被 `sr-item` 拦截）。需要先清空搜索或点击别处关闭浮层。

**自测交互：有形式、没闭环。** 每章"验收自测"默认折叠（"👆 点击展开自测（先作答再对照）"），点击展开正常。但如上所述，**没有任何参考答案**——"对照"环节缺失，选择做完不知道对错。这是自测功能价值打折的一半以上。

**代码复制：按钮存在、实际失效。** 每个代码块有"复制"按钮，但在当前 http 环境下点击报 console TypeError（`navigator.clipboard` undefined），无降级方案、无失败提示。根因链条：https 证书仍是 `*.github.io`（自定义域 SSL 未生效）→ 用户只能走 http → clipboard API 不可用 → 复制按钮全站失效。对一本大量代码示例的书，这个 bug 的伤害不小——我是想复制 1.7 的 eval.ts 拿去跑的。

**评估大全页（benchmarks/）：超出预期的惊喜。** 65 个评估体系卡片，按 13 家厂商引用量倒排（GPQA Diamond 11 家引用排第 1），每张卡固定三行："测什么 / 评分协议 / 评分方式"，支持类别筛选（知识与学科 9、代码与工程 10……）和实时搜索（我输入 "swe" 正确过滤到 3 条、GPQA 消失）。这页本质上是第 14 章覆盖矩阵的可交互版，是我以后查"这个基准是干嘛的"的第一入口。导航栏的"下载 EPUB"入口也直接可用。

**HTTPS：不可用。** 如上，证书错误。对一个 2026 年上线的站点，这应该排进修复清单第一位——不只是为了 clipboard，还因为书里第 21 章教的就是安全评估。

## 我读完能做什么了

具体的 capability 变化清单（都是读完这 9 章后新增的）：

1. **看懂厂商发布会的分数表**：能用五问法（协议/采样/子集/锚点/缺席）拆解任意一份发布材料，能识别代际锚、限定赛道锚、"+550% 先找基数"，能判断"这个数字是测量结果还是营销数字"。下次组里讨论"要不要换成新模型"我能有实质发言权。
2. **区分 pass@1 / pass@k / cons@k**：知道"没有标注采样口径的代码/推理分数默认不可比"，知道为什么同一模型同一基准能合法差 8 个点。
3. **从零写一个能进 CI 的评估器**：按第 17 章 30→100→150 行的路径，我知道要有什么——判官统一签名、结构化输出、mapPool 有界并发、Wilson 区间、EvalRun 快照落盘、`process.exitCode` 门禁。`npm i openai` 就能起步。
4. **解释"MMLU 高 ≠ agent 强"**：能引用"同档 86-88 分的模型在 SWE-bench 可差约 30 个百分点"和"维度独立失败"的论证（16.5.3），能看懂为什么 agent 评估要看轨迹不只看终态。
5. **知道自建评估集怎么起步**：100 题以内就能起步（1.4）、判官上岗前抽 50-300 条人工标注算一致率、κ ≥ 0.7 才上线（3.5.3、17.7.2）、PR 快集/夜间全量/发版安全集/在线采样的四层结构及各自阈值语义（17.6）。
6. **看分数先要置信区间**："100 题 70% → [60.4%, 78.1%]"，两个模型差 2 个点在百题量级就是噪声。这条会改变我以后看任何 A/B 数据的方式。
7. **对评估系统本身保持怀疑**：Gold patch 自检（7.5.4）、判官金标准集回归（17.7.2）、ABC 清单三问（7.5.7）——评分器自己也是需要被测试的代码。

## 最希望改进的 5 件事

1. **自测补答案**。每道选择题给一个折叠的"查看答案 + 一句解析"，简答给要点式参考。这是对学习闭环伤害最大、修复成本最低的一项——尤其第 31 章是"结课自测"，做完无处对照很难受。
2. **修复代码复制**。两步：等自定义域 SSL 签发完成让 https 可用；复制按钮加 `document.execCommand('copy')` fallback 和失败 toast，别让按钮在 http 下静默无效。
3. **第 3 章 3.4.3 补一句 API 现实**：likelihood 比较路线需要 logprobs 能力或本地模型，托管 chat API 用户直接走 generation-based。这一句能救每个拿着 `gpt-4o-mini` 硬试的初学者十分钟。
4. **首页搜索浮层不拦截下方点击**（点空白处或失焦时收起），另外给第 3 章 3.6 开头加"读不懂代码就记住这三个结论"的分层出口。
5. **第 2 章 9 调用点表格对应用层读者减负**：给每行加"与你有关吗"标注（①-⑥ 标"训练侧，了解即可"），或把 ⑦⑧⑨ 提前。我猜这本书的多数读者是我这种人，不是训练工程师。
