# 站点评审清单 —— 读者任务测试矩阵

> 来源：2026-08-31 全站评审复盘。当时四个核心缺陷（自测无交互、引用未复用组件、
> 时间轴评测点击进空页、评测覆盖不全）全部漏检——根因不是功能没做，而是**验收视角单一**。
> 本清单是修正后的最低验收口径：任何页面/功能交付前，逐条以"读者任务"视角实测，
> 不允许仅以"构建者视角功能可用"作为完成标准。

## 一、四类验收视角（缺一不可）

| 视角 | 代表问题 | 测法 |
|---|---|---|
| **学习者**（初级前端读者） | 我做完这道题能立即知道对错吗？我搜一个术语能到解释页吗？我点了一个链接会到空页吗？ | 以读者任务走完学习闭环：读→练→自测→查证 |
| **查询者**（查评测的人） | 我搜 SWE-bench 能到评测页吗？时间轴里罗列的每个评测都能点进去吗？ | 从时间轴/搜索/详情页三入口抽查评测可达性 |
| **UI 新人**（视觉一致性） | 新旧组件混色了吗？间距/圆角/强调色成体系吗？暗色下可读吗？ | 同页新旧组件对比 + 明暗双主题截图 |
| **工程师**（回归与数据） | 校验器绿吗？数据 schema 合法吗？证据可溯源吗？ | validate:site + validate:data + 抽查 locator |

## 二、覆盖审计口径（自上而下）

1. **以证据账本为准，不以存量卡片为准**：凡在 `data/model-releases/**` 证据中出现的
   benchmark id，必须在站点上有详情页（正式实体或证据自动建档）。对账：
   证据 id 集合 − 实体 id 集合 = 0。
2. **凡罗列必可点击**：列表/时间轴/卡片里出现的任何条目，点击必须落到非空详情页；
   数据缺失时页面显式标注缺口，而不是渲染成死文本或空页。
3. **缺失信息三选一**：deep-research 补全 / 显式标注"待深研"（保留已知信息）/ 不展示。
   禁止：渲染成不可交互元素假装不存在。

## 三、组件复用检查

- 同一数据实体（如 release×benchmark 证据边）在多处展示时，必须共用同一渲染函数与
  同一份 CSS，不允许每页手写一份表格/卡片。
- 新页面引入已有数据的展示时，先找现有组件；找不到再建，且建时放共享层。

## 四、交互完整性（真实点击，不信任静态检查）

- 每个可交互控件（筛选/排序/搜索/展开/复制）真实点击一次并断言结果变化。
- 每个列表的空态要有恢复操作（清除筛选/放宽条件）。
- 筛选与搜索状态同步到 URL query；清除后 URL 同步清理。
- 键盘：Tab 顺序、焦点可见、skip-link；交互控件有 aria-pressed/expanded 等状态。
- 明暗双主题 + 360px 宽度各过一遍；无横向溢出；内容不贴屏幕边缘。

## 五、多视角评审闭环

重大改版后，派 ≥2 个互不相干的评审 agent 分别以上表不同视角实测（真实浏览器交互），
问题回归修复后再收口。评审发现的问题按"根因→可泛化检查项"回写本清单。

## 六、需求选型与模型覆盖回归（2026-09-23，#1 / #2）

- 从“中文长文”解析维度后，立即核对可见权重、报告与 URL；刷新及浏览器后退应重现同一状态，不能只改表单。
- 清除筛选只点一次，检查控件、结果数和 URL 同时恢复；原生 reset 与异步渲染的先后顺序不能造成第二次点击才生效。
- 360px 下打开时间轴筛选下拉框，检查最长选项不会撑宽页面；桌面测试不能替代窄屏实测。
- 同一发布包含多个模型时，逐条分数必须带模型/变体名；四个 Gemma 规格独立展示，不能把首个模型的规格复制给全家族。
- 有图片但未转录的成绩显示“图表尚无可读数值”，与“官方未公布数值”分开；两者都不能当作 0 参与筛选或排序。
- 基准的适用范围放在读数附近，进入来源可看到 locator、协议、日期和限制；不要求读者读到底部才发现不能比较。
- 覆盖页逐厂商展示入口失败及回填队列；入口已读取不等于历史模型已穷尽。每个 release 的官方链接、归档和模型详情都能相互定位。
