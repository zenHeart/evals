如何开始使用 M3.1-Flash-Preview

尝试文档案例或更新既有 API 集成前，先完成这四项检查。

  1. Step.01

    确认权限与模型

    打开 MiniMax Code，检查账号可选的模型。本页只传递文本 Prompt，不会自动选择或开通 M3.1-Flash-Preview。使用 API 时，指南规定的模型 ID 如下。 仅为 model 字段，不是完整 API 请求: { "model": "MiniMax-M3.1-Flash-Preview" }

  2. Step.02

    提供任务所需的真实素材

    编程任务需提供仓库、复现方式和验收标准；研究任务需提供数据来源与截止日期；视觉任务需上传原始图片或视频。本页案例仅作参考，点击 CTA 不会自动传递案例文件。

  3. Step.03

    检查思考与输出设置

    模型始终开启思考。指南默认推荐 Max effort，同时提供 Low、Medium、High、Xhigh 四档。迁移时移除 thinking.type=disabled 和 effort=none，否则请求会报错；为思考过程和最终回答留出足够输出预算。

  4. Step.04

    使用结果前先验证

    读取 reasoning_content 前先判空；更新依赖 reasoning_details 或 <think> 标签解析的代码。验证代码测试和浏览器交互，复核表格公式与信源，检查视觉结果。文档案例展示可能的工作方式，不是所有任务的效果保证。

了解模型能力、真实案例来源与接入边界。

M3.1-Flash-Preview 是所提供指南中面向高频编程、金融研究、多模态理解与前端工作场景的 MiniMax 模型。指南列出其采用 MoE 架构，总参数量 428B、约 23B 激活参数，并使用稀疏注意力与原生视觉编码器。

支持。指南说明模型接受文本、图片、视频输入，输出文本。在具备工具的环境中，可结合代码和图像处理工具完成找不同、图表结构化和视频分镜分析。这与原生生成图片或视频是不同能力。

预览指南列出 1,000,000 token 上下文窗口和约 150 tokens/s 的速度。实际速度受负载、输入输出长度影响，该数字不是端到端任务耗时保证。
